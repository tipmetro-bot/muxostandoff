# Прокси проверки Standoff 2 ID

Маленький сервис, который отдаёт сайту `muxostandoff` настоящий ник по Standoff 2 ID.

Сайт статический и работает с магазином `store.standoff2.com` напрямую не может:
магазин отвечает `403 Invalid CORS request` на любой чужой `Origin` и `403` от Cloudflare
на простые HTTP-запросы из дата-центров. Единственный рабочий путь — настоящий браузер,
который открывает магазин, вводит ID и показывает ник. Этот прокси так и делает:
Playwright с Chromium, один раз на процесс, с кэшем и CORS.

```
GET /?id=1234567   ->  200 {"nick": "Nickname"}
GET /?id=0000000   ->  404 {"error": "not found"}
GET /health        ->  200 {"ok": true, "mode": "browser", "cache": 3}
```

Контракт совпадает с тем, что сайт ждёт от `verifyEndpoint`: `200 {"nick": "..."}` — успех,
`404` — «ID не найден в Standoff 2», остальное — «Проверка ника недоступна».

---

## Установка

Нужен Python 3.9+ и ~350 МБ на Chromium.

```bash
cd proxy
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
playwright install chromium
```

## Запуск

```bash
python3 verify.py --port 8787
```

Проверка, что сервис живой:

```bash
curl http://127.0.0.1:8787/health
curl "http://127.0.0.1:8787/?id=ВАШ_ID"
```

Один запрос с сохранением страницы магазина (для отладки селекторов):

```bash
python3 verify.py --calibrate ВАШ_ID
```

Положит рядом `store-page.html` и `store-captured.json` — по ним видно, что вернул магазин
и какие элементы есть на странице.

## Выдать сайту доступ

Сайт живёт на `https://tipmetro-bot.github.io`, а прокси — на вашей машине. Два варианта.

**Туннель (проще, без белого IP):**

```bash
cloudflared tunnel --url http://127.0.0.1:8787
```

Утилита [cloudflared](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/)
выдаст адрес вида `https://random-words.trycloudflare.com`. Он живёт, пока запущен процесс.
Туннель каждый раз новый, поэтому адрес придётся обновлять в `index.html`.

**Свой сервер с доменом:** запустите прокси на VPS и поставьте перед ним nginx/caddy с TLS,
либо оставьте как есть и используйте `--origin` с адресом сайта.

Дальше в `index.html`, в блоке `CONFIG`:

```js
verifyEndpoint: "https://random-words.trycloudflare.com/?id={id}",
```

Перезагрузите сайт. В окне регистрации исчезнет пометка «демо-проверка» и ссылка на магазин,
а ник будет приходить от прокси.

## Проверка связки без браузера

Пока Chromium не установлен или магазин недоступен, можно убедиться, что сайт и прокси
друг друга понимают:

```bash
python3 verify.py --stub --port 8787
```

`--stub` не открывает браузер: ID, оканчивающийся на `0`, даёт `404`, любой другой —
`200` с ником `Stub_XXXX`. Удобно, чтобы проверить CORS и `verifyEndpoint`, не ставя Chromium.

## Флаги

| Флаг | Что делает |
| --- | --- |
| `--host` | адрес прослушивания, по умолчанию `127.0.0.1` (наружу не торчит) |
| `--port` | порт, по умолчанию `8787` |
| `--origin` | разрешённый Origin сайта, можно несколько раз; по умолчанию `*` |
| `--cache-ttl` | сколько секунд кэшировать ник, по умолчанию `3600` |
| `--headful` | показывать окно браузера, удобно для отладки |
| `--stub` | без браузера, детерминированная заглушка |
| `--calibrate ID` | один запрос, дамп страницы и перехваченного JSON |

Не публикуйте прокси без `--origin` и не выставляйте `--host 0.0.0.0` в интернет без
необходимости: сервис запускает браузер на каждый промах кэша, и им легко занять машину.
Для домашнего использования `127.0.0.1` + туннель достаточно.

## Как достаётся ник

1. Chromium открывает `https://store.standoff2.com/ru-RU`.
2. Проверяется, не показал ли Cloudflare проверку браузера (`Just a moment…`, `Attention Required`).
   Если показал — пауза и повторное чтение страницы, при неудаче `502`.
3. ID вводится в поле с плейсхолдером `ID` (перебирается несколько вариантов селектора).
4. Нажимается кнопка поиска (перебор по текстам «Найти», «Искать», «Поиск», «Продолжить»),
   иначе Enter.
5. Ник берётся из перехваченного ответа магазина (`/api/...` → JSON, поиск ключей
   `nickname` / `nick` / `name`), а если ответа нет — из DOM по набору селекторов.
6. Результат кэшируется: успех на `--cache-ttl`, отказ — на 5 минут.

## Если не работает

**`cloudflare challenge не пройден`.** Магазин усиленно проверяет headless-браузер.
Попробуйте `--headful` (окно будет видно, но проверка часто проходит), затем повторите
`--calibrate`. Иногда помогает подождать и запустить снова.

**`не найдено поле для Standoff 2 ID`.** Вёрстка магазина изменилась. Запустите
`--calibrate ID`, откройте `store-page.html` и найдите `input` рядом с надписью ID:
имя класса или `placeholder` подскажут новый селектор. Правится в словаре селекторов
в `verify.py`.

**`502` и в логе `playwright`-ошибки.** Проверьте, что Chromium установлен:
`playwright install chromium`. На Linux без графики иногда нужны зависимости:
`playwright install-deps chromium` (нужен root).

**Сайт пишет «Проверка ника недоступна».** Прокси не отвечает, либо CORS не совпал:
запустите с `--origin https://tipmetro-bot.github.io` и убедитесь, что туннель жив.
Проверка `curl -i "https://адрес-туннеля/?id=1234567"` покажет заголовки.

**Ник не находится, хотя ID верный.** Магазин мог вернуть профиль, но без ника в JSON
(только аватар). Откройте `store-captured.json` из `--calibrate` и посмотрите структуру:
если ник лежит под другим ключом, добавьте его в `NICK_KEYS`.

## Ограничения

* Один браузер на процесс и блокировка на время запроса: одновременные проверки встают в очередь.
  Для хвх-рума этого с запасом хватает.
* Магазин может в любой момент поменять вёрстку или усилить защиту — тогда ник ломается,
  а сайт автоматически возвращается к демо-режиму, без падения.
* Это неофициальная интеграция: запросы идут от вашего IP, и решать, укладываетесь ли вы в
  правила магазина, вам.
