# muxostandoff

ХВХ-рум для Standoff 2: комнаты только для читер против читера. Чистым игрокам здесь нечего делать.

Сайт — один файл `index.html` (HTML + CSS + JS внутри). Без сборки, без npm, без внешних библиотек и CDN.
Работает и по `file://`, и на GitHub Pages.

```
index.html    весь сайт
README.md     этот файл
.nojekyll     отключает Jekyll на GitHub Pages
```

---

## Быстрый старт

1. Открыть `index.html` двойным кликом. Сайт сразу работает в локальном режиме.
2. Зарегистрироваться: Standoff 2 ID (7–12 цифр) → «Проверить» → ник подтягивается из проверки → пароль.
3. Создать комнату, скопировать код `MX-AB12` и позвать второго игрока.

Локальный режим хранит аккаунты и комнаты в `localStorage` браузера. Комнаты видны только в этом браузере
и только на этом устройстве — другие люди их не увидят.

## Firebase Realtime Database (общие комнаты)

Пока `databaseURL` пустой, сайт работает локально. Чтобы комнаты стали общими, подключите базу.

### 1. Создать проект

1. Открыть [console.firebase.google.com](https://console.firebase.google.com/), «Создать проект».
2. В проекте: **Build → Realtime Database → Create Database**.
3. Выбрать регион (например, `europe-west1`) и режим **Test mode**.
4. Скопировать ссылку вида `https://xxx-default-rtdb.europe-west1.firebasedatabase.app`.

### 2. Вписать ссылку в сайт

В `index.html`, в самом верху `<script>`, есть блок настроек:

```js
const CONFIG = {
  databaseURL: "",      // https://xxx-default-rtdb.europe-west1.firebasedatabase.app
  verifyEndpoint: "",   // проверка ника: вернуть {"nick":"Ник"} или 404
  demoVerifyDelay: 700
};
```

Вставить ссылку без завершающего `/` и без `.json`:

```js
databaseURL: "https://xxx-default-rtdb.europe-west1.firebasedatabase.app",
```

Перезагрузить страницу. Внизу должно появиться «база: облако · список общий для всех».
С этого момента список комнат общий для всех, кто открыл сайт, а изменения приходят в реальном времени.

### 3. Rules

**Test mode** открывает базу на чтение и запись всем, у кого есть ссылка. Это простой вариант для игры
«свои против своих», но данные может испортить любой, кто узнает адрес базы. Правила по умолчанию:

```json
{
  "rules": {
    ".read": true,
    ".write": true
  }
}
```

Более аккуратный вариант — открыть только нужные ветки:

```json
{
  "rules": {
    "users": {
      ".read": true,
      ".write": true
    },
    "rooms": {
      ".read": true,
      ".write": true
    },
    "friends": {
      ".read": true,
      ".write": true
    },
    "presence": {
      ".read": true,
      ".write": true
    },
    "dm": {
      ".read": true,
      ".write": true
    },
    "dmMeta": {
      ".read": true,
      ".write": true
    },
    "calls": {
      ".read": true,
      ".write": true
    },
    ".read": false,
    ".write": false
  }
}
```

Новые ветки (`friends`, `presence`, `dm`, `dmMeta`, `calls`) появились вместе с друзьями и звонками.
Если оставить только `users` и `rooms`, сайт откроется, но друзья и звонки работать не будут:
запросы вернут `Permission denied`, а в интерфейсе будет пустой список вместо ошибки.

Быстрый способ опубликовать правила: Firebase Console → Realtime Database → вкладка **Rules** →
вставить JSON выше → **Publish**. Через CLI: `firebase deploy --only database`.

Важно: у сайта нет своего бэкенда и нет Firebase Auth. Клиент пишет в базу напрямую, поэтому любые
ограничения на сервере не смогут отличить владельца комнаты от постороннего. Проверки «только владелец
может править и удалять» и «пароль комнаты» работают в интерфейсе. Если нужна настоящая защита — нужен
свой прокси/бэкенд и Firebase Auth, это уже другая задача.

### Как сайт работает с базой

| Операция | Запрос |
| --- | --- |
| список комнат | `GET {databaseURL}/rooms.json` |
| аккаунт | `GET {databaseURL}/users/{standoffId}.json` |
| регистрация | `PUT {databaseURL}/users/{standoffId}.json` |
| создать комнату | `PUT {databaseURL}/rooms/{roomId}.json` |
| правка комнаты | `PATCH {databaseURL}/rooms/{roomId}.json` |
| удалить комнату | `DELETE {databaseURL}/rooms/{roomId}.json` |
| live-обновления комнат | `new EventSource("{databaseURL}/rooms.json")`, события `put` / `patch` / `cancel` |
| друзья и заявки | `GET/PUT {databaseURL}/friends/{standoffId}.json`, статусы `in` / `out` / `friends` |
| присутствие | `PUT {databaseURL}/presence/{standoffId}.json` (`at`, `nick`), читается целиком |
| переписка | `GET/PUT {databaseURL}/dm/{id~id}/m/{messageId}.json`, превью в `dmMeta/{id~id}` |
| звонки | `PUT {databaseURL}/calls/{id~id}/offer|answer|state|end|ice/...` |

Записи отправляются с `Content-Type: text/plain`, чтобы браузер не делал CORS-preflight: Firebase
одинаково разбирает JSON в теле запроса. Чтение и поток идут обычным GET.

Если `databaseURL` пустой или база недоступна (нет сети, неверная ссылка, закрыты правила), сайт сам
переключается на `localStorage`. Внизу страницы это видно по строке состояния:

* `база: облако · список общий для всех` — Firebase подключён;
* `база: локально (только у тебя)` — `databaseURL` пустой;
* `облако недоступно · локальный режим` — база была указана, но не ответила.

## Проверка ника Standoff 2

Публичного API Standoff 2 у сайта нет, поэтому по умолчанию работает **демо-проверка**:
ник считается детерминированно из ID — один и тот же ID всегда даёт один и тот же ник,
задержка около 0.7 секунды, на кнопке «Проверяю…». Аккаунт создать без успешной проверки нельзя,
и ник вручную не вводится.

Чтобы подключить настоящую проверку, укажите `verifyEndpoint` — свой маленький прокси:

```js
verifyEndpoint: "https://your-proxy.example.com/standoff?id={id}",
```

Контракт:

* запрос `GET` (плейсхолдер `{id}` заменяется на ID; если плейсхолдера нет, ID добавляется как `?id=`);
* успех — HTTP 200 и JSON `{"nick": "Ник"}`;
* ID не найден — HTTP 404 (сайт покажет «ID не найден в Standoff 2»);
* остальные ошибки — тост «Проверка ника недоступна».

Прокси нужен потому, что браузер не может обратиться к официальному магазину Standoff 2
(`store.standoff2.com`) напрямую. Это проверено запросами, а не предположение:

| Запрос | Ответ |
| --- | --- |
| `GET /api/v2/productsConfig/{id}` с `Origin: https://tipmetro-bot.github.io` | `403 Invalid CORS request` |
| `GET /api/player/{id}` с `Origin: https://example.com` | `403 Invalid CORS request` |
| `GET /api/player/{id}` без `Origin` | `404 {"code":"40013"}` — API живой, но только для своих |
| `POST /api/v2/accounts` с `{uid}` | `403` от Cloudflare, даже без `Origin` |

Магазин отдаёт `vary: Origin` и отвергает **любой** чужой `Origin`. Браузер всегда подставляет свой
`Origin` на межсайтовый запрос и не позволяет его убрать, поэтому со статической страницы на GitHub
Pages прочитать ответ магазина невозможно — ни с какими настройками сайта. Остаётся только серверный
прокси, которому вы доверяете.

### Готовый прокси в репозитории

В папке [`proxy/`](proxy/) лежит рабочий сервис: Python + Playwright открывает магазин,
вводит ID и отдаёт `{"nick": "..."}` с CORS. Это единственный вариант, который действительно
возвращает настоящий ник — обычные HTTP-запросы магазин режет.

```bash
cd proxy
pip install -r requirements.txt
playwright install chromium
python3 verify.py --port 8787
```

Дальше туннель `cloudflared tunnel --url http://127.0.0.1:8787` и адрес в `verifyEndpoint`.
Подробно — в [`proxy/README.md`](proxy/README.md): запуск, `--stub` для проверки связки без
браузера, `--calibrate` для дампа страницы и разбор типичных ошибок.

### Рецепт прокси (Cloudflare Worker)

```js
export default {
  async fetch(request) {
    const cors = {
      'Access-Control-Allow-Origin': 'https://tipmetro-bot.github.io',
      'Content-Type': 'application/json; charset=utf-8'
    };
    const id = new URL(request.url).searchParams.get('id') || '';
    if (!/^\d{7,12}$/.test(id)) {
      return new Response(JSON.stringify({ error: 'bad id' }), { status: 400, headers: cors });
    }
    // запрос уходит с сервера, без Origin — магазин такой принимает
    const res = await fetch('https://store.standoff2.com/api/v2/accounts', {
      method: 'POST',
      headers: { 'content-type': 'application/json' },
      body: JSON.stringify({ uid: id })
    });
    if (!res.ok) {
      return new Response(JSON.stringify({ error: 'upstream ' + res.status }), { status: 404, headers: cors });
    }
    const data = await res.json();
    const nick = data && (data.nickname || data.nick || data.name);
    if (!nick) {
      return new Response(JSON.stringify({ error: 'no nick' }), { status: 404, headers: cors });
    }
    return new Response(JSON.stringify({ nick: String(nick) }), { status: 200, headers: cors });
  }
};
```

Дальше впишите адрес воркера в настройки и перезагрузите страницу:

```js
verifyEndpoint: "https://your-worker.workers.dev/?id={id}",
```

Честное предупреждение: `POST /api/v2/accounts` защищён Cloudflare и с серверных IP отдаёт `403`.
С запросами из дата-центров (включая Cloudflare Workers и GitHub Actions) он, скорее всего, не
заработает; на домашнем/резидентском IP шансы выше. Если прокси упрётся в `403`, реальная проверка
потребует браузерной автоматизации (Playwright/Puppeteer в связке с вашим прокси) — это уже отдельный
сервис, а не статический сайт. Пока прокси не подключён, сайт работает в демо-режиме, и в интерфейсе
это прямо написано: «демо-проверка», плюс ссылка на официальный магазин, где свой ник видно вручную.

## Как выложить на GitHub Pages

### Вариант 1: через сайт GitHub

1. Создать публичный репозиторий, например `muxostandoff`, без автоинициализации.
2. Загрузить в корень `index.html`, `README.md`, `.nojekyll`.
3. **Settings → Pages → Build and deployment**: Source `Deploy from a branch`, Branch `main`, папка `/ (root)`.
4. Дождаться сборки и открыть `https://{owner}.github.io/muxostandoff/`.

### Вариант 2: через git и API

```bash
git init
git add index.html README.md .nojekyll
git commit -m "muxostandoff"
git branch -M main
git remote add origin https://github.com/{owner}/muxostandoff.git
git push -u origin main

gh api --method POST repos/{owner}/muxostandoff/pages \
  -f "source[branch]=main" -f "source[path]=/"
```

Проверка:

```bash
gh api repos/{owner}/muxostandoff/pages/builds/latest
curl -I https://{owner}.github.io/muxostandoff/
```

`.`nojekyll` обязателен: без него GitHub Pages прогоняет файлы через Jekyll, и это может ломать
отдачу статики. Сайт работает и без сборки — это просто статический `index.html`.

Если позже впишете `databaseURL`, помните: файл `index.html` лежит в публичном репозитории, ссылка на
базу тоже будет видна всем. Секретов в ней нет, но правила доступа к базе надо настроить.

## Что умеет сайт

* **Аккаунты по Standoff 2 ID** — регистрация только после проверки ID, ник берётся из проверки,
  пароль хранится хешем (FNV-1a, не крипто), сессия переживает перезагрузку.
* **Смена ника** — клик по нику в шапке: 2–20 символов, лишние пробелы и управляющие символы
  вычищаются. Новый ник сразу подставляется в шапку, карточку хоста, слоты, чат и панель комнаты.
  Проверенный ник из Standoff 2 не теряется: он хранится в `verifiedNick` и показан в подсказке.
* **Комнаты** — 1x1, 2x2, 3x3, 4x4, 5x5 и «Свой размер» на 2/4/6/8/10/12/14 слотов (до 7x7).
  Название до 42 символов, обязательный стиль чита, карта, регион, необязательные пароль и пинг.
* **Стиль чита** — легит / семи-рейдж / рейдж, бейдж на карточке и в окне комнаты, отдельный фильтр со счётчиками.
* **Комната** — код `MX-AB12` с копированием, команды A и B, занятые и свободные слоты, полоса
  заполненности, «Занять слот» / «Выйти» / «Готово».
* **Хост** — тот, кто создал лобби, подписан везде: на карточке («хост: ник · ID 1234567»),
  строкой «Хост» с Standoff 2 ID в окне комнаты и меткой `хост` в своём слоте команды A.
  По Standoff 2 ID хоста работает поиск, ID виден всем, кто открыл сайт.
* **Статус матча** — бейдж на карточке и баннер в окне комнаты: `лобби` → `в игре`
  (в комнате минимум два игрока и все занятые слоты нажали «Готово») → `итог A/B` после фиксации.
* **Проверка победы** — панель «Результат»: каждый участник голосует за команду A или B и может
  передумать, пока не проголосовали все. Когда голоса всех участников совпали, результат
  фиксируется (`result.winner`, `result.settledAt`), в шапке растёт счётчик побед, хост может нажать
  «Реванш» — готовность и результат сбрасываются.
* **Чат комнаты** — `rooms/{id}/messages`, до 200 символов, один серверный лимит в секунду на игрока,
  автоматическая прокрутка, удаление своего сообщения (чужие удалить нельзя).
* **Голосовой чат** — WebRTC-mesh между участниками комнаты, разрешение на микрофон спрашивается
  браузером, отказ объясняется тостом «Браузер не дал доступ к микрофону — разреши его в адресе сайта»,
  есть mute и выключение. Голос продолжает работать, когда окно комнаты закрыто: он снимается при
  выходе из комнаты, удалении комнаты, выходе из аккаунта и закрытии вкладки — тогда уходит `bye`
  и микрофон освобождается.
* **Панель комнаты поверх страницы** — как виджет участников в Discord: пока ты в комнате и окно
  комнаты закрыто, слева снизу висит панель с названием, кодом, статусом и списком игроков
  (команда, «готов», «в голосе»), кнопками «Открыть комнату», микрофоном и сворачиванием.
  Кнопка «Поверх окон» выносит её в отдельное окно Document Picture-in-Picture (Chrome/Edge 116+),
  которое остаётся поверх других окон; в остальных браузерах показывается честная подсказка.
* **Права** — править и удалять может только владелец, удаление подтверждается вторым кликом.
  Владелец не может «выйти» из своей комнаты: только удалить. У чужой комнаты кнопок правки нет.
* **Пароль комнаты** — при входе поле, сверка по хешу, ошибка «Неверный пароль».
* **Список** — фильтры «Все», форматы, «Свой», «Мои» и стиль чита; поиск по названию, карте, региону,
  нику и Standoff 2 ID хоста, никам игроков и стилю; сортировка: сначала неполные комнаты, потом новые.
* **Пустая база** — это норма: «Пока никто не создал комнату. Будь первым.» Никаких демо-комнат и
  придуманных игроков, список наполняют только реальные люди.
* **Чистка мусора** — в список попадают только комнаты, которые реально можно создать в интерфейсе.
  Комнаты с пустым Standoff 2 ID, без игроков, без названия и брошенные комнаты, где больше трёх часов
  сидит один хозяин, скрываются из списка, фильтров и счётчиков и удаляются из базы. Свою комнату,
  в которой ты сидишь, чистка не трогает.
* **Вкладки** — всё не сваливается в одну страницу: в шапке два раздела, «Комнаты» со счётчиком
  и «Читы». Вкладка помнит себя в адресе (`#cheats`), переключается стрелками ← → с клавиатуры,
  кнопка «Создать комнату» всегда возвращает на «Комнаты».
* **Фон на выбор** — окно «Вид» в шапке: сетка, звёзды, соединяющиеся точки или пустой фон,
  плотность (мало / средне / много) и выключатель анимации. Живой фон рисуется на canvas под
  контентом, не перехватывает клики, сам тормозит на скрытой вкладке и уважает
  `prefers-reduced-motion`. Выбор хранится в браузере (`mx_ui`).
* **Темы** — чёрная и белая, переключатель ☀ / ☾ в шапке или в окне «Вид», выбор запоминается.
* **Читы** — отдельная вкладка: Exodium (оригинал, платный) и ZeninLoader (кряк), к каждому
  приложены нужные файлы со скачиванием, размерами и SHA-256.
* **Друзья** — вкладка «Друзья» в шапке со счётчиком заявок и непрочитанных. Поиск по Standoff 2 ID
  или нику, заявки (входящие / исходящие), принять, отклонить, отменить, удалить из друзей
  (удаление подтверждается вторым кликом). Рядом с ником видно, в сети человек или нет, и его ID.
* **Переписка** — личный чат с другом: сообщения до 1000 символов, экранирование HTML, время,
  пометка своих сообщений, счётчик непрочитанных, тост на новое сообщение, история в базе.
* **Звонки** — кнопка «Звонок» у друга: голос, камера и демонстрация экрана (Chrome/Edge на компьютере).
  Входящий звонок появляется панелью поверх страницы на любой вкладке сайта, с кнопками «Принять» /
  «Отклонить». В активном звонке есть микрофон, камера, «Экран» и «Завершить», идёт таймер.
  Звонить можно только друзьям — спам-звонков нет.
* **Мобильная вёрстка** — карточки в одну колонку, команды A/B друг под другом, фильтры переносятся,
  друзья и переписка встают друг под друга.

## Читы и файлы

Вкладка «Читы» в шапке (`#cheats`). Часть файлов лежит в корне репозитория и отдаётся самим
сайтом (например `https://tipmetro-bot.github.io/muxostandoff/Exodium(4).exe`), часть — в релизах:

* [`DSASSAD`](https://github.com/tipmetro-bot/muxostandoff/releases/tag/DSASSAD) — актуальный, после
  патча Standoff 2: `Exodium.5.exe` и `neptunium.pc.loader.1.4-f1.3.zip`;
* [`fgd`](https://github.com/tipmetro-bot/muxostandoff/releases/tag/fgd) — предыдущий: старый
  `neptunium.pc.loader.1.4-f1.1.zip` и установщик BlueStacks под Neptunium.

### Сначала включи ADB

Все читы подключаются к эмулятору через ADB, без него они не увидят игру:

1. Открой BlueStacks → «Настройки» (шестерёнка).
2. Вкладка «Дополнительно» → «Android Debug Bridge».

## Чистка старых комнат

В облачной базе могут остаться записи, которые сайт создать не может: кто-то пишет в Firebase напрямую,
а правила открытые. Сайт их не показывает и удаляет сам, но если вкладка закрыта, чистить некому —
поэтому есть workflow:

```bash
# раз в час по расписанию или вручную
gh workflow run cleanup-rooms.yml --repo tipmetro-bot/muxostandoff
```

Он читает `rooms.json`, печатает таблицу «комната / код / хост / игроки / создана / решение» и удаляет
записи по тем же правилам, что и сайт. Отчёт попадает в Summary запуска.

Удаляется только это:

| Случай | Признак |
| --- | --- |
| нет Standoff 2 ID | `ownerId` не 7–12 цифр |
| нет игроков | `players` пустой |
| без названия | `name` пустое или «Без названия» |
| брошена | старше `staleRoomHours` (3 ч) и в ней один игрок |

Живую комнату с двумя и более игроками чистка не удаляет никогда.

---

## Схема данных

```js
users/{standoffId} = { id, nick, verifiedNick?, pass, createdAt, wins?, winRooms?, nickChangedAt? }

rooms/{roomId} = {
  name, mode,            // "1x1".."5x5" | "custom"
  cap,                   // всего слотов
  map, region, ping,
  style,                 // "legit" | "semi" | "rage"
  passHash, ownerId, ownerNick, code, createdAt,
  players: { "{playerId}": { id, nick, at, ready? } },
  messages: { "{msgId}": { uid, nick, text, at } },
  result: { votes: { "{playerId}": "A" | "B" }, winner: "A" | "B" | "", settledAt },
  voice: { "{signalId}": { from, to, kind, nick, sdp, candidate, at } }
}
```

Отличия от минимальной схемы, о которых стоит знать:

* `ping` — необязательное число мс, вводится при создании/правке; `null`, если не указан.
* в объекте игрока есть необязательное поле `ready` (bool) — это состояние кнопки «Готово»;
  без него отметку готовности негде хранить в заданной схеме.
* `roomId` — ключ в базе, внутри объекта комнаты его нет; `id` есть только у пользователя.
* `passHash` у комнаты — `hash(пароль + код комнаты)`, у аккаунта — `hash(пароль + ID)`.
  Хеш простой и детерминированный, это защита «чтобы не лежало открытым», а не криптография.
* `code` — публичный код вида `MX-AB12`, он уникален среди существующих комнат.
* `messages` — текст режется до 200 символов, управляющие символы заменяются пробелами, при выводе
  всё проходит через `esc()`. `uid` нужен, чтобы удалять только свои сообщения.
* `nick` — текущий ник, который виден всем; `verifiedNick` — ник, полученный при проверке ID, он
  сохраняется при первой смене и показывается в подсказке. `nickChangedAt` — время последней смены.
  Смена ника обновляет `ownerNick` в своих комнатах и `players/{id}/nick` во всех комнатах, где ты
  сидишь; старые сообщения в чате остаются под прежним ником — это история.
* `result.votes` — голоса «кто выиграл», пишутся только участниками; когда голоса всех участников
  совпали, клиент фиксирует `winner` и `settledAt`. Повторно результат не начисляется: в
  `users/{id}.winRooms` запоминается `roomId → settledAt`.
* `voice` — сигнализация WebRTC: `hello` (метка присутствия с сердцебиением), `offer`, `answer`,
  `candidate`, `bye`. Записи старше 60 секунд удаляются клиентами, своя метка `hello` — при выходе.
  Голос идёт напрямую между браузерами, через базу ходят только SDP и ICE-кандидаты.

В локальном режиме те же объекты лежат в `localStorage` под ключами `mx_users`, `mx_rooms`,
`mx_session`, `mx_theme`.

## Друзья и звонки: как это устроено

**Присутствие.** Раз в 25 секунд браузер пишет в `presence/{Standoff 2 ID}` время и ник. Если запись
старше 80 секунд, человек считается офлайн. При выходе из аккаунта время сбрасывается в `0`, чтобы
друзья сразу видели «не в сети».

**Заявки.** В `friends/{мой ID}/{его ID}` лежит `{id, nick, status, at}`, статус `out` — я отправил,
`in` — мне отправили, `friends` — друзья. Заявка пишется сразу в обе стороны, поэтому не нужно
отдельное дерево уведомлений.

**Переписка.** Ключ треда — два ID по возрастанию: `42073869~42073870`. Внутри `dm/{тред}/m/{id}`
сообщения `{from, nick, text, at}`, в `dmMeta/{тред}` — последнее сообщение для превью и счётчика.
Непрочитанное считается по локальной отметке в `localStorage` (`mx_dmSeen`), она не уходит в базу.

**Звонки.** Один общий тред на пару друзей: `calls/{тред}`. Тот, кто звонит, кладёт `offer` и
`state.phase = "ring"`, второй отвечает `answer`, дальше стороны обмениваются ICE-кандидатами в
`ice/{ID}/{ключ}`. Завершение — `end` и `state.phase = "ended"`, через 2.5 секунды тред удаляется.
Сайт опрашивает `calls.json` раз в 6 секунд и при открытии вкладки «Друзья», поэтому звонок доходит
без перезагрузки страницы.

Что важно знать про звонки:

* **Оба должны быть на сайте.** Пушей и фоновых уведомлений нет — если друг закрыл вкладку, звонок
  ему не придёт. Дозвониться можно только тому, кто сейчас в сети (и это видно по метке в списке).
* **STUN без TURN.** По умолчанию используется `stun:stun.l.google.com:19302`. За жёстким NAT и в
  мобильных сетях часть звонков не соединится. Свой TURN вписывается в `CONFIG.iceServers`:

  ```js
  iceServers: [
    { urls: 'turn:turn.example.com:3478', username: 'user', credential: 'secret' }
  ]
  ```

  TURN-сервер придётся поднять самому (например, coturn) — бесплатного общего TURN для публичного
  сайта не бывает.
* **Браузер.** Нужны Chrome, Edge или Safari с поддержкой WebRTC. Демонстрация экрана есть на
  компьютере (Chrome/Edge); на телефоне вместо неё доступны голос и камера.
* **Разрешения.** Микрофон и камера спрашиваются браузером. Отказ объясняется тостом
  «Браузер не дал доступ к микрофону — разреши его в адресе сайта».

## Ограничения

* Проверка ника по умолчанию демонстрационная (см. выше).
* Кто угодно с доступом к базе может писать в неё напрямую — интерфейсные проверки прав и пароля
  не заменяют серверную авторизацию.
* Одновременное вступление двух игроков в последний свободный слот может переполнить комнату:
  REST без транзакций. Для игры «свои против своих» это редкий и поправимый случай.
* Восстановления пароля нет: аккаунт привязан к ID, при утере пароля нужен новый ID.
* Локальный режим не синхронизируется между браузерами и устройствами.
* Голосовой чат требует `https://` или `localhost` (иначе браузер не даст микрофон) и работает через
  STUN без TURN: в редких сетях со строгим NAT соединение не установится — останется чат текстом.
* Отдельное окно панели («Поверх окон») есть только в Chrome и Edge 116+; в Firefox и Safari этот API
  отсутствует, там панель просто висит поверх страницы.
* Смена ника свободная: проверить, что ник уникален или принадлежит владельцу ID, нельзя — именно
  поэтому проверенный ник хранится отдельно и показывается рядом.
* Правила чистки — клиентские: порог «брошена» задаётся в `CONFIG.staleRoomHours` (по умолчанию 3 ч).
  Если все вкладки закрыты, мусор убирает GitHub Actions (`.github/workflows/cleanup-rooms.yml`,
  раз в час), поэтому база чистится и без открытого сайта.
* Чистка удаляет только то, что интерфейс не создаёт: запись с пустым `ownerId`, комнату без игроков,
  безымянную комнату и комнату старше `staleRoomHours` с единственным игроком. Настоящую живую комнату
  двух и более игроков она не удалит никогда.
  Микрофон запрашивается только по кнопке, звук никуда не пишется и не сохраняется.
* Голос — mesh: каждый с каждым. Для комнат на 5x5 и больше это заметная нагрузка на канал.

## Проверка

Сайт прогнан автотестами на DOM (jsdom) с реальными HTTP и SSE-запросами к мок-базе, повторяющей
REST-семантику Firebase. Проверены: пустой список, полный цикл регистрации и входа, ошибки входа,
создание комнаты с паролем, вступление вторым аккаунтом, неверный пароль, правка, удаление вторым
кликом, фильтры и поиск, заполненная комната, темы, сохранение сессии, живое обновление двух браузеров
через SSE, деградация в локальный режим, `file://`, экранирование HTML.

Тесты лежат в `tests/` и запускаются как `cd tests && npm install && node smoke.mjs` (остальные файлы
так же: `node features.mjs`, `node pip.mjs`, `node junk.mjs`, `node tabs.mjs`, `node social.mjs`).
Последний прогон:

* `smoke.mjs` — **45/45**: читы (3 карточки, ссылки на релиз и локальные файлы, SHA-256 совпадает с
  байтами, ADB-инструкция), пустое лобби, регистрация, комната, панель комнаты, смена ника
  (валидация, обрезка пробелов, обновление в комнате, сохранение в сессии), сворачивание панели,
  темы, чистая консоль;
* `features.mjs` — **37/37**: чат с XSS и удалением, статус «в игре», голосование и фиксация
  единогласия, счётчик побед, реванш, смена ника в слотов и новых сообщениях, отказ микрофона,
  голос, mute из панели, `bye` при закрытии вкладки;
* `pip.mjs` — **13/13**: панель переезжает в Document Picture-in-Picture, кнопки работают из
  отдельного окна, при закрытии окна панель возвращается на страницу;
* `junk.mjs` — **9/9**: мусорные комнаты не показываются и удаляются из базы, живая комната остаётся,
  своя старая комната не удаляется;
* `tabs.mjs` — **35/35**: три вкладки и `aria-selected`, адрес `#cheats`, счётчик комнат и сводка
  в интро, окно «Вид» (сетка / звёзды / точки и линии / пусто), плотность, выключатель анимации,
  тема из окна вида, сброс, закрытие по Esc, сохранение выбора после перезагрузки, чистая консоль;
* `social.mjs` — **43/43**: вкладка «Друзья», гостю предлагают войти, поиск по ID, заявка в обе
  стороны, приём заявки, счётчик-бейдж, список друзей, личная переписка двух аккаунтов (включая
  экранирование HTML и снятие непрочитанного), исходящий звонок (offer, микрофон, mute, отмена),
  входящий звонок (панель, принять, answer, таймер, демонстрация экрана, завершение), отмена вызова
  звонящим и повторный звонок, удаление из друзей с подтверждением, чистая консоль.

WebRTC и PiP проверены на заглушках `RTCPeerConnection`, `getUserMedia` и `documentPictureInPicture`:
реальный звук и отдельное окно в песочнице не воспроизводятся.
